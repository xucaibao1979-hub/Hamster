# 企业微信项目间免密登录：给 AI 开发助手的通用规则

将本文交给负责**其他项目**的 AI 开发助手时，先填写文末“项目参数”。本文是实现要求，不代表目标项目已经具备这些接口。请先检查目标项目现有的登录、会话、权限、员工身份和部署方式，再按其技术栈实现；不要直接复制资盒代码。

## 目标与边界

源项目负责验证企业微信登录身份并展示“进入目标系统”的入口；目标项目负责颁发一次性票据、建立自己的网页会话，并独立判断用户能看什么、能做什么。员工无需逐个创建目标系统的本地密码账号。任何浏览器传入的姓名、UserID 或角色都不能直接成为登录或管理员权限依据。

## 必须遵守的规则

1. **可信身份**：源项目从已验证的企业微信会话取得 `wecomUserId`。姓名仅用于展示，重名人员必须以 UserID 区分。源项目服务端对调用目标项目的身份负责，浏览器不得直接调用换票接口。
2. **服务鉴权先于身份处理**：目标项目先校验双方共享的、至少 32 位的服务凭证，再处理 `X-WeCom-UserId` 等身份头。凭证只保存在双方后端配置中，不得进入前端、跳转 URL、代码库、日志或错误消息。
3. **目标项目自行授权**：目标项目按 UserID 查其已登记且在职的员工，并重新计算权限。普通员工只能访问本人范围；管理员权限仅来自目标项目内明确的管理员授权或目标项目允许的已关联账号角色。源项目的入口授权本身不能自动赋予目标项目管理员权限。停用员工或停用的关联账号必须拒绝免登。
4. **后端换票**：源项目后端以 `POST` 调用目标项目的换票接口，请求体可为 `{}`。成功时目标项目返回 JSON `loginUrl` 和 `expiresIn`，换票接口本身不重定向。`loginUrl` 必须属于目标项目预先配置的 HTTPS 公开域名，不得由请求 `Host` 头拼接。
5. **一次性票据**：使用密码学安全随机数生成不可预测的票据；建议有效期 60 秒，只能核销一次。服务端仅保存票据摘要。核销必须原子执行，先删除票据再建立网页会话，防止并发重放。多实例部署必须使用共享且支持原子删除的存储；单实例内存存储会在重启时使未核销票据失效。
6. **浏览器会话**：用户浏览器打开 `loginUrl` 后，由目标项目设置自己的 `Secure; HttpOnly; SameSite=Lax` Cookie，并以 303 跳转到不含票据的首页。网页会话在后续每次请求中重新核对员工在职和管理员授权，保证撤销立即生效。目标项目仍应执行原有接口权限、CSRF/Origin 检查和退出登录规则。
7. **响应与日志**：凭证错误返回 401；身份不存在、停用或无权进入返回 403；票据失效或重复使用返回 400；业务失败返回包含 `error` 的 JSON。所有涉及票据的响应禁止缓存。应用及反向代理日志不能记录完整票据；`/sso/consume` 访问日志应遮盖查询参数。
8. **兼容现有功能**：不得改变原有密码登录、业务接口、资产/用户数据、审批流转或数据备份的行为。新增免登须有独立测试并通过原有回归测试。

## 接口模板

源项目后端请求：

```http
POST https://<目标域名>/api/sso/ticket
Authorization: Bearer <目标项目服务凭证>
X-WeCom-UserId: <从已验证企业微信会话取得的 UserID>
X-WeCom-Name: <URL 编码后的企业微信姓名>
X-WeCom-Department: <可选部门>
Content-Type: application/json

{}
```

成功响应：

```json
{
  "loginUrl": "https://<目标域名>/sso/consume?ticket=<一次性票据>",
  "expiresIn": 60
}
```

源项目只把 `loginUrl` 交给**当前已验证用户**的浏览器打开；不要提前批量换票或缓存链接。目标项目核销成功后建立自己的会话并跳转首页。源项目不应把长期服务凭证、管理员标记或任意用户名放入 `loginUrl`。

## 给 AI 的实施顺序

1. 阅读目标项目现有的认证中间件、会话存储、员工资料、管理员授权、反向代理和测试；写出身份与权限映射，并指出是否需要预先同步企业微信 UserID。
2. 实现服务端换票、一次性票据核销和目标项目网页会话；所有新路由遵守目标项目现有代码结构。
3. 在目标项目管理界面提供或复用按 UserID 授权管理员的机制。若已有“审批管理员”，**先确认其授权范围**；只有业务明确要求时才将其映射为完整网页管理员。
4. 补齐源项目入口与后端调用。源项目必须先验证企业微信身份，并只将服务凭证用于服务端请求。
5. 编写配置、接口、部署、故障排查文档；用普通员工、管理员和停用员工分别在手机与电脑企业微信联调。

## 最低验收用例

- 无凭证或错误凭证换票为 401；未知、停用或缺少 UserID 为 403。
- 返回的 `loginUrl` 仅位于目标项目指定的 HTTPS 域名，且不包含长期服务凭证。
- 票据在有效期内只可兑换一次；过期、重放、并发重复兑换均不能再创建会话。
- 核销响应包含安全 Cookie 和不含票据的跳转地址；直接浏览器打开页面能保持目标项目会话。
- 普通员工只能查询本人数据，不能调用管理员接口；已明确授权的管理员可以访问其授权范围。
- 撤销管理员授权或停用员工后，已有免登会话在下一次请求立即失去相应权限。
- 原有密码登录、业务接口和备份恢复测试继续通过。

## 资盒当前实例（供参考，不要机械套用）

资盒公开域名为 `https://zchub.saybot.net`；源项目 IT小爱配置 `HAMSTER_SSO_TICKET_URL=https://zchub.saybot.net/api/sso/ticket` 和 `ASSET_HUB_SERVICE_TOKEN`，资盒配置 `APP_ORIGIN=https://zchub.saybot.net`、`COOKIE_SECURE=true` 和相同值的 `IT_SERVICE_TOKEN`。资盒员工以 `wecomUserId` 识别；“设置 → 集成中心 → IT小爱管理员授权”中的 UserID 可通过免登获得资盒管理员权限。实现细节见 [资盒免密认证使用手册](SSO.md)。
